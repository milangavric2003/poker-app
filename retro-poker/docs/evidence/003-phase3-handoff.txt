STVARNI API I DTO
POST /api/game/coach: strict JSON <=1024 UTF-8 bytes, body
{gameId,handId,expectedVersion,goal:{focus:'betting'|'street'|'showdown'}}.
202 created/running;200 stopped/insufficient_evidence bez provider/tool poziva.
Aktivni isti goal/fingerprint vraća isti runId; drugi goal409.
GET /api/game/coach/:runId: UUID path, prazni strict query;200 isti zadržani run.
Unknown/zamenjen run404, malformed400. Jedna forma, bez query endpoint-a.
Response CoachResponseSchema={run:CoachRunViewSchema}; run ima UUID identity,
factsRevision, goal, status, ISO startedAt/deadlineAt, step/tool/provider counters,
stopReason/failureCategory, sampleLimited i result=null osim validiranog completed.
Svi odgovori imaju no-store. GameErrorSchema additive codes:
GAME_NOT_TERMINAL,COACH_ALREADY_PENDING,RUN_NOT_FOUND. Week04 GameView ne menja se.
UsageResponseSchema na postojećem GET /api/ai/usage dobija strict coach agregat;
legacy DTO bez coach ostaje prihvaćen. Backend uvek šalje coach.

LOCK, ASYNC I PRIVATNOST
Session poseduje jedan in-memory run slot i AbortController. Start/status/commit
koriste postojeći serial. Provider/tool await je izvan lock-a; queued reservation
garantuje dispatch posle oslobađanja start lock-a. GET i nova partija ne čekaju mrežu.
Orchestrator pravi deep-cloned/frozen server-side terminal MatchFacts snapshot.
isCurrent i commit porede runId/gameId/handId/version/factsRevision. Nova partija
uklanja slot pre abort-a, provider može ignorisati signal ali race/checkpoint odbaci
rezultat. Dupli POST aktivnog run-a ne dispatch-uje novi rad; terminalni eksplicitni
POST pravi novi UUID i zamenjuje prethodni slot. Orchestrator terminal guard i
session committed flag sprečavaju duplu finalizaciju/upis usage-a. T015 validator
stoji pre completed; public whitelist projection nikad ne šalje proposal/tool output,
prompt, exception, API key ili interno stanje. Poker/RNG/history/facts ne menjaju se.
